Executive Summary

The Hound security team conducted this comprehensive audit of the Tokemak protocol architecture, with emphasis on its shared system services, vault infrastructure, asset deployment mechanisms, swapping components, oracle integrations, statistics calculations, and reward and staking integrations.

The review covered the system architecture, including SystemRegistry and AccessController governance services; destination vault and LMP vault registries and factories; strategy and destination adapter boundaries; external AMM routing and token transfers; oracle providers and pricing flows; statistics calculators; and integrations with external gauges, staking systems, and reward protocols.

The architecture presents clear separation between registries, factories, vaults, adapters, routers, oracles, and external protocols. The supplied review data contains no recorded security findings, so the observed security posture is based on the documented component relationships and interfaces rather than confirmed vulnerability results. External integrations, privileged access controls, token movement, oracle assumptions, and factory registration flows remain critical areas for continued validation.

System Overview

The Hound team identified SystemRegistry and AccessController as shared system services supporting protocol configuration and authorization. AccessController implements IAccessController and governs defined roles while depending on SystemRegistry, establishing a centralized control boundary for privileged operations. Components such as DestinationVaultRegistry also depend on SystemRegistry and the destination-vault factory interface, making registry configuration and role administration important security dependencies.

The vault subsystem is organized around factory and registry patterns. DestinationVaultFactory creates and initializes DestinationVault instances before registering them with DestinationVaultRegistry. LMPVaultFactory creates LMPVault instances and associated AbstractRewarder components, while LMPVaultRegistry tracks the resulting vault infrastructure. IStrategy depends on the DestinationVault abstraction, and destination adapters such as CurveV2FactoryCryptoAdapter, MaverickAdapter, and VelodromeStakingAdapter implement shared adapter interfaces for asset deployment, pool interaction, and staking operations.

Our analysis revealed a swap layer centered on SwapRouter, which implements ISwapRouter, validates synchronous swapper behavior through ISyncSwapper, and routes requests to CurveV2Swap and UniV3Swap. These components transfer external ERC-20 and pool tokens and interact with external AMM pools and routers. The primary security boundaries include route and adapter selection, token approvals and custody, transfer accounting, slippage and output validation, and protection against unsafe or unexpected external call behavior.

Oracle and valuation flows use IPriceOracle-compatible components, including IRootPriceOracle, ChainlinkOracle, EthPeggedOracle, WstETHEthOracle, and BalancerLPMetaStableEthOracle. ChainlinkOracle depends on external oracle providers, WstETHEthOracle reads from the root-price oracle, and the Balancer implementation reads from external AMM state. StatsCalculatorFactory creates CurveV1ConvexStatsCalculator, which implements IStatsCalculator and computes pool statistics, while incentive-pricing statistics consume external token data and root-price information. These flows require careful treatment of stale, manipulated, inconsistent, or incorrectly scaled pricing data.

Reward and staking integrations extend the protocol into external gauges and reward systems. AbstractRewarder implements IMainRewarder and computes reward information involving external tokens, while ConvexRewardsAdapter, BeethovenRewardsAdapter, and MaverickRewardsAdapter implement IClaimableRewardsAdapter for reward claims. DestinationVault can claim through MaverickRewardsAdapter, and VelodromeStakingAdapter stakes through external reward protocols. Our analysis therefore treats reward claiming, staking authorization, callback and token handling, accounting of claimed assets, and the trustworthiness of external protocol responses as material security considerations.
